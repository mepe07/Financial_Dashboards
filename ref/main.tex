\section{Introdução}

No ecossistema bancário e empresarial português, a troca eficiente de informação financeira é fundamental para a gestão de tesouraria. Neste contexto, o formato PS2 (Protocolo de Serviço) assume um papel preponderante, sendo o padrão utilizado pela SIBS para a normalização de ficheiros de cobranças por Débito Direto (SEPA).

Estes ficheiros caracterizam-se pela sua estrutura posicional rígida (ficheiros de texto de largura fixa), onde cada linha representa um registo específico — cabeçalhos, movimentos ou rodapés — e cada posição contém dados vitais como NIFs, montantes, entre outros. Devido a esta natureza técnica e pouco legível para o utilizador comum, a validação e análise manual destes documentos torna-se ineficiente e propensa a erros humanos.

\subsection{O Desafio Proposto}
O desafio proposto no âmbito da Unidade Curricular de Laboratórios de Informática consistiu no desenvolvimento de uma solução de software robusta capaz de facilitar a visualização da informação, recorrendo a dashboards e outras ferramentas que possam ser úteis. O sistema deveria ser capaz de:
\begin{enumerate}
    \item \textbf{Ingerir} ficheiros de texto em bruto, interpretando a lógica posicional do formato PS2;
    \item \textbf{Validar} a integridade dos dados (verificação de totais de controlo e estrutura dos registos);
    \item \textbf{Visualizar} a informação transformada através de métricas e gráficos intuitivos.
\end{enumerate}

\subsection{Solução Orquestrada}
Para responder a estes requisitos, foi orquestrada uma solução modular desenvolvida na linguagem Python. A arquitetura do projeto baseia-se na biblioteca \textit{Pandas} \cite{mckinney2012} para a manipulação vetorial e eficiente de grandes volumes de dados, garantindo performance no processamento dos registos.

Para a interface com o utilizador, optou-se pela framework \textit{Shiny for Python} \cite{shiny2024}, permitindo a criação de vários \textit{dashboards} web interativos que escondem a complexidade do código, apresentando ao utilizador final apenas os indicadores de gestão e as validações de erro necessárias.



\subsection{Objetivos}
Os objetivos principais definidos para este projeto foram:
\begin{itemize} % Uso de Itemize (Requisito)
    \item Desenvolver um leitor de ficheiros de PS2.
    \item Criar validações automáticas de integridade dos ficheiros e dados neles contidos.
    \item Apresentar dados em \textit{dashboards} interativos.
\end{itemize}

\section{Resultados}
A aplicação gera visualizações gráficas utilizando a biblioteca \textit{Matplotlib} \cite{hunter2007}, sendo que apresenta também, em formato de tabela, os dados retirados dos ficheiros PS2, permitindo a utilização de filtros para facilitar a procura por algum dado em específico.
Além de permitir filtragem dos dados por data, permite também procurar informação relativa a um cliente em específico ou até apenas num ficheiro PS2 em concreto.
Para dar o máximo controlo ao utilizador final, é ainda permitida a desativação/ativação de gráficos conforme o pretendido.

\subsection{Análise Gráfica}
A visualização de dados desempenha um papel crucial na interpretação dos grandes volumes de informação contidos nos ficheiros PS2. Para o efeito, foram implementados cinco tipos de gráficos distintos, gerados dinamicamente com base nos dados carregados:

\begin{enumerate}
    \item \textbf{Top Entidades:} Um gráfico de barras que destaca as entidades com maior volume de transações, permitindo identificar rapidamente os principais intervenientes.
    \item \textbf{Evolução Mensal:} Um gráfico de linhas que ilustra o comportamento dos montantes ao longo dos meses, facilitando a deteção de sazonalidade.
    \item \textbf{Evolução Global:} Uma visualização acumulada que permite compreender a tendência geral de crescimento ou decréscimo do volume financeiro processado.
    \item \textbf{Histograma:} Gráfico de distribuição de frequências que ajuda a compreender a dispersão dos valores das transações (e.g., predominância de pequenos movimentos vs. grandes montantes).
    \item \textbf{Diagrama de Pareto:} Uma análise combinada (barras e linha) que aplica a regra 80/20, demonstrando quais os clientes a quem as entidades mais cobram, permitindo perceber quais são os seus melhores clientes.
\end{enumerate}

\section{Conclusão}
O desenvolvimento deste projeto constituiu um desafio técnico enriquecedor, permitindo a aplicação prática de conceitos de Engenharia de Software num contexto financeiro real. A principal dificuldade enfrentada residiu na implementação de um \textit{leitor} robusto para o formato posicional PS2, onde a gestão rigorosa de índices e a validação de inconsistências nos dados brutos se revelaram críticas.

Contudo, a superação destes obstáculos permitiu aprofundar significativamente o domínio sobre as bibliotecas \textit{Pandas} e \textit{Shiny}, consolidando a importância de uma arquitetura modular e escalável. Em suma, a solução final não só cumpre integralmente os requisitos de automação e visualização propostos, como também demonstra a eficácia de ferramentas \textit{open-source} na modernização de processos de análise de dados bancários, eliminando o erro humano associado ao tratamento manual.
